# 0.0.1 任务清单

目标是两版词典：**核心版 117,902 词条起、完整版 811,092 词条起，两版逐词附离线音频**。数字来自当前固定输入；重新构建时必须重算。旧的 5,000 词核心包、无音频包和只含 436 条录音的带音频包是开发期旧候选，不是新版 0.0.1 成品。没有推送、PR、tag 或 Release。

| 顺序 | 要做什么 | 验收时看什么 |
| --- | --- | --- |
| 1. 固定词条范围 | 核心版选入所有 `origin=curated` 词条，再选入有 ECDICT `frq`、`bnc` 或考试标签的缺词。保留每条入选词条的完整 `leximeet.entry.v1` 内容。完整版保留全部词条。 | 当前固定输入分别为 84,212 + 33,690 = **117,902** 和 **811,092**；核心版的 `entry_id` 全部存在于完整版，词义、来源和标签未被缩减。 |
| 2. 补齐逐词离线音频 | 复用已核验的 436 条 Commons 录音；其余录音需使用有明确可再分发依据的来源或在本地用固定版本的语音引擎与语音模型生成。先小批量试产，测生成速度、体积和试听质量，再批量生成；失败可续跑。记录真人/合成、口音、输入文本、引擎/模型版本、许可、文件 SHA-256。 | 对核心版和完整版分别做 `entry_id` 覆盖核对，**每条至少有一段真实存在、可解码的随包音频**；坏文件、空文件、缺署名或仅有在线 URL 都算失败。抽查多读音、缩写、专名和异常词，修正不合理发音；不能把自动抽样说成真人听辨完成。 |
| 3. 改为两个发布版本 | 打包器与校验器只生成 `core`、`full` 两个版本；核心版包括完整词卡及其全部音频，完整版包括全量词条、索引及其全部音频。按体积将版本拆成带哈希的下载分片，保证单个 Release 资产小于 2 GiB。 | 从零构建、解包、逐文件校验、词条数和音频覆盖数均通过；核心版能作为 Chromium 插件和桌面端的内置文件，完整版能按清单完整下载并替换。旧三包名称不再出现在新版 Release 清单和流水线。 |
| 4. 核验交付 | 更新构建命令、两版准确体积、SHA-256、数据与录音署名、README 和 CHANGELOG；让 CI 验证同一套固定输入和音频锁。 | 单元测试、全量完整性校验、样本解码与打包校验通过，`generator.dirty=false`；清单只列两版，所有已知失败都已处理。核心版若超过插件发布渠道限制，须先解决分发方式再声称“可内置”。 |
| 5. 发布 | 维护者检查实际音质、词义风险、体积和清单后自行推送 `main`、打 tag、上传 Release。 | 客户端可按 [消费契约](CLIENT_CONTRACT.md)校验并安装；本仓库只证明词包可用，客户端原生接入测试由各消费项目负责。 |

**音频是当前最大缺口。** 现有 53,121 条候选 URL 只覆盖 29,189 个策展词条，且未逐文件核权；它们不能直接变成 81 万条可分发录音。不要批量调用免费在线朗读服务抓取后再分发，也不要把系统 TTS 当成已随包提供的文件。若找不到可再分发且音质可接受的生成方案，0.0.1 不应宣称达到这个新版目标。

压缩实测：84,212 条完整策展词卡本身使用 Brotli 9 约 **76 MB**；只取简短释义、英文原义和音标约 **11 MB**，却会失去原词卡的大量解释、例句与溯源，因此核心版不采用裁剪。现有 436 条 OGG 合计 **5.79 MB**，仅按其平均时长和 Opus 6 kb/s 估算，84,212 条录音就约 **47 MB**（不含封装和词卡）；这是规划估算，不是生成后的实际包大小。Opus 的推荐语音码率通常高于最低 6 kb/s（[RFC 6716](https://www.rfc-editor.org/rfc/rfc6716#section-2.1.1)），必须在试产时以音质与体积实测决定。

## 0.0.2（不挡 0.0.1 的来源计划）

评估 DictionaryByGPT4 的助记内容及 qwerty-learner 的词表归属，只导入已核实可分发、质量可接受的部分；都不覆盖基础词义。WordNet 义项对齐与更多发音变体按实际需求推进。
