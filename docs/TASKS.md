## 阶段 0：固定数据输入与发布范围（P0）

- [ ] DIC-00 确认首版语言范围为英语词头 + 简体中文解释，定义“词条、可用义项、缺词回退、离线查询”的计数口径。输出一页指标字典和 200 个以上分层样本（常见词、罕见词、词组、专名、同形异义、大小写、英美多音、ECDICT-only）。
- [x] DIC-01 获取 open-dictionary v2.0 的 distribution.jsonl.gz、audit.jsonl.gz、SHA256SUMS.txt，核对发行方校验和并保存压缩/解压文件 SHA-256、字节数、URL、日期及许可证。压缩文件已本地校验；解压内容通过流式读取，不落盘，非压缩 distribution 的上游哈希见 SOURCE_LOCK。无法取得 audit 时，缩小溯源与自动义项对齐范围，并在报告中写明。
- [x] DIC-02a 对主词源筛选规则遗漏的 article/conj 高功能词，固定 Kaikki 的 34 个逐词原始文件哈希，提取 161 条英文短义及标签；仅向缺失词性新增独立来源义项，不跨快照按词头对齐，也不复制历史引文。
- [ ] DIC-02 优先寻找与 v2.0 同谱系的 2025-10-23 Wiktextract 快照。若不可获取，可改用指定日期的其他快照，但必须记录差异，并把跨快照义项连接归为候选，不启用按词头自动合并。全量新版 Kaikki 解压约 23.9 GB，且与 v2.0 的快照不同；完成原始数据锁定、容量与对齐方案前不导入全量包。可先使用有固定版本的小样本验证管线；正式导入在容量足够的隔离存储中流式解压，只保留 lang_code=en。
- [x] DIC-03 锁定 Open English WordNet 2025 Edition 的一个正式数据文件及哈希；核 ECDICT/CMUdict 本地哈希；补齐 sources.lock.json 的已选数据工件哈希、许可证与署名记录，并在构建器中校验锁文件。不得将 Git submodule SHA 代替数据文件 SHA。
- [x] DIC-04a 对 ECDICT 记录原仓库、MIT 文本、贡献者致谢和权利通知邮箱；维护者决定不把历史资料逐字段追溯作为首版单独发布门禁。收到具体权利主张时核查并移除或替换。
- [ ] DIC-04b 对 GPT 长文和 qwerty 各词表分别记录来源与使用许可；未完成者在发布配置中保持禁用。

阶段 0 完成条件：每个被启用的输入都有固定 bytes、SHA-256、来源文件与适用声明；首版来源清单能回答“这个字段从哪个文件哪条记录而来”。ECDICT 使用已记录的署名与权利通知策略；新的 GPT/qwerty 来源未完成独立评估前不进入默认包。

## 阶段 1：语义契约与导入器（P0）

- [ ] DIC-10 确定 LexemeEntry、Sense、Pronunciation、LabelAssertion、WordlistMembership、SynsetMapping、SourceRecord、AudioAsset 的 schema，并明确哪些字段可空。将用户 UserWord/UserTag/WordBook 与公开词典 schema 分开；提供中英文字段说明和示例。
- [ ] DIC-11 建立词头规范化与同形异义规则：Unicode、大小写、连字符、缩写、短语、变形、词性和词源分组；规则版本化。对 May/may、bank、record、read 建固定反例。
- [ ] DIC-12 建立独立稳定 entry_id/sense_id 与发行间映射账本。open-dictionary 的 s1 等顺序 ID 仅作带发行版的 source_ref；定义拆分、合并、删除时的重定向与人工复核流程。
- [ ] DIC-13 实现四个独立导入器：open-dictionary distribution/audit、Wiktextract English、ECDICT、CMUdict；WordNet 为后续独立导入。每个导入器保留原值和定位，不在导入阶段覆盖别的来源。
- [ ] DIC-14 建立 JSONL schema 校验和源引用完整性校验：UTF-8、重复 ID、悬空引用、未知语言/地区/标签、无来源字段、异常长度、损坏压缩包均能报告或拒绝。

阶段 1 完成条件：固定样本可重复导入，输入相同则规范输出相同；无重复/悬空 ID，原值可回溯；单元测试覆盖所有上述反例。每个新增模块附中文注释、设计决策与迭代记录。

## 阶段 2：义项和标签融合（P0）

- [ ] DIC-20 建立候选对齐器：先匹配词头/语言/词性/词源，再比较英文原义、限定词和例句。输出自动通过、待审、拒绝三态及理由；跨快照默认待审。保存人工决策以供重建复用。
- [ ] DIC-21 制定字段选择器：open-dictionary 学习者解释优先；Wiktextract 英文原义与标签按核准义项补充；ECDICT 中文在未对齐时只作词条级回退。冲突与多候选不被静默丢弃。
- [ ] DIC-22 将 open-dictionary labels/topics 与 Wiktextract sense.tags/topics 归一化成领域、语法、语域、时代、地区等有 scope 的断言；同源谱系去重，不把词条 categories 一律当义项标签。未知标签保留原文待审。
- [ ] DIC-23 解析 ECDICT 显式 exam tag，明确只是来源收录声称；保留 bnc/frq、collins、oxford 的原字段和缺失语义。先不要发布 qwerty 的词表成员关系。为未来合法词书设计 Wordlist 与 Membership 导入接口。
- [ ] DIC-24 制作审计报告：按来源统计词头交集/独有量、义项自动对齐与拒绝量、字段覆盖率、标签冲突率、中文回退率。对分层样本人工标注“误合并、漏合并、错词性、错标签”，关键误合并必须修复后重跑。

阶段 2 完成条件：200 个以上分层样本有可追溯人工判定，发布候选中无已知错义项挂载；样本量、错误数量和误配率均公开。不能用“词头匹配率”代替义项准确率。

## 阶段 3：词包与客户端契约（P0）

- [ ] DIC-30 生成规范 JSONL 与 manifest：稳定排序、输入/输出哈希、schema、许可、署名、构建 commit、规则版本、ID 重定向、字段覆盖和审计报告。相同输入可重复构建并复核内容哈希。
- [ ] DIC-31 由规范层生成桌面端只读 SQLite：词头与词形索引、义项索引、词表关联索引及必要全文索引。测试前缀查找、大小写、词组、变形和多音词，记录包大小与 p50/p95 查询时延。
- [ ] DIC-32 生成插件核心包与可选扩展分片：无网能查询核心词，扩展包按需下载和哈希验证。记录首次装载、内存、磁盘与 p50/p95 查询时延，不把完整词典一次性装入内存。
- [ ] DIC-33 制定跨端只读查询接口与中英文本地化词条展示：返回来源、标签作用域和缺失状态；旧客户端遇到新 schema 时安全拒绝并保持旧包。
- [ ] DIC-34 在隔离的桌面/浏览器测试配置中验证安装、断网、升级、损坏包拒绝、回滚、旧 ID 重定向、用户笔记/单词本不丢失。用真实客户端路径做集成和端到端测试。
- [x] DIC-35 把已构建的 `core.jsonl.gz` 连同同版 manifest、许可证和 SHA-256 做成插件可独立下载的核心资产；全量新资产已重建并通过归档哈希、词条 schema/ID、损坏拒绝和隔离安装抽验。
- [ ] DIC-36 手动触发的 GitHub Actions 候选构建流水线已写入源码：固定数据下载、哈希校验、完整构建、报告、固定音频清单重建及复核、三资产打包和按选择上传一个候选资产。只给读取权限，不自动创建 tag 或 Release；远端首跑与人工审校/客户端验收尚未完成，故整项不打勾。

阶段 3 完成条件：两端对同一固定样本返回相同词条语义；查询时延和体积有机器/平台说明；词包更新失败可恢复上一版；用户私有库未被重建。指标目标应在取得首次基线后写入发布门禁，不能用臆造数字先宣称达标。

## 阶段 4：音频与扩展能力（P1/P2）

- [ ] DIC-41 做缓存和署名：缓存键包含文本/地区/音色/语速/提供方/版本；保留来源、许可证、时效与删除入口。为 Commons 候选建立逐文件作者、许可、链接、文件哈希审核；未经审核不进入公开音频包。
- [ ] DIC-42 导入 WordNet 2025 core 并建立 sense→synset 证据、置信度和待审队列；展示同义、上位、反义等有向关系。不把同词头的所有 synset 都挂到主义项。
- [ ] DIC-43 导入 CMUdict 多读音与重音；如做 ARPAbet→IPA，保存转换规则版本及原文，对 read/record/lead 抽样校验。

- [ ] DIC-45 另寻有明确词表权利的考试/教材资源，逐词表固定版本与许可证后才能接入 Membership。qwerty 词书只能在原始权利可核查时逐本评估，不以 GPL 代码许可替代数据授权。

阶段 4 完成条件：音频权限与缓存测试通过，离线无网场景稳定；WordNet/CMUdict/AI/词表模块可关闭且不会改变已发布核心词条身份。

## 持续发布纪律

每次实现任务记录中文迭代文档、测试命令及结果、失败环境、源码 commit 与建议 Git message；更新 CHANGELOG 和来源清单。构建测试、数据质量审核、署名材料和客户端真实路径测试分别给出证据。首次公开发布前保留 CC BY-SA/CC BY/CMUdict/ECDICT 的相应许可文本与署名，以及权利通知入口。维护者已明确表示由其本人在 0.0.1 完成后推送；本地开发不推送代码、不发布词包，也不批量拉取或缓存有使用限制的在线音频。
