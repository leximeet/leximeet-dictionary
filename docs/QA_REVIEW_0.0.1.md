# 0.0.1 分层词义与音频复核记录

日期：2026-09-28。对象是 `build/v0.0.1-final/` 的固定本地候选，与 `dist/final/release-candidate.json` 中的三份归档使用同一词典正文。本页区分**程序一致性检查**、**本轮编辑筛查**、**ASR 辅助转写**和**尚未完成的独立词义/真人听辨判断**，避免将不同强度的证据混写成“250 条全部人工通过”。

## 210 条词义样本

从 `qa/review-sample.csv` 逐条按 `entry_id` 重读只读 SQLite，对照词头、来源层、义项数、前两条英文原义与中文学习解释、ECDICT 中文回退，并核对义项 `display_order` 连续、领域/用法标签属于义项、考试标签属于词条。`tools/audit_samples.py` 将结果写到 `build/v0.0.1-final/qa/`，并把可审阅的小文件固定到 [词义复核表](qa/0.0.1/agent-meaning-review.csv) 与 [汇总](qa/0.0.1/agent-review-summary.json)。**210/210 条在这些源字段与结构检查上通过**；这只证明工作表确实对应当前词包，不证明释义本身正确。

| 抽样层次 | 条数 | 本轮能判断什么 |
| --- | ---: | --- |
| 策展词条 | 107 | 看到了 open-dictionary 的义项预览、中文学习解释、英文 audit 短原义和标签作用域；仍未逐条对照独立词典的全部义项 |
| ECDICT 底座词条 | 103 | 可检查词条级中文/英文回退及来源；其中 99 条没有逐义项结构，不能把单行翻译说成已核准逐义双语词卡 |
| 合计 | 210 | 源字段/结构一致性 210 条通过；编辑疑点 9 条需修正或回查 |

编辑筛查读过 210 条工作表的词头及释义预览。以下疑点是**定位清楚的后续处理项**；没有将 ECDICT 原始字段直接改写成假装来自原库的新事实。

| 词头 | 发现 | 对 0.0.1 的处理方向 |
| --- | --- | --- |
| `a` | 词条级中文混合字母名、冠词和计算机缩写；冠词义项还没有逐义中文 | 核准独立的冠词中文解释，保持原 ECDICT 回退另列 |
| `the` | ECDICT `art. 那` 不能概括定冠词；新增 article 英文义项无逐义中文 | 给核心冠词义项补审校中文，不把 `那` 强贴到所有义项 |
| `hell chicken` | 英文原义写明 `Anzu wyliei` 为兽脚类恐龙，策展中文却称“阿祖翼龙” | 修正中文名称并保留原字段与修订来源记录，再重建词包 |
| `regressively` | ECDICT 英文是副词 `In a regressive manner.`，中文为形容词“回归的” | 复核具体语境和词性后提供词遇修订，不篡改原 ECDICT 字段 |
| `scrumhalfs` | ECDICT 仅给“前锋”，与 rugby scrum-half 的位置术语有疑问 | 查专业来源后修正或标为待核 |
| `Ltd` | 仅给“有限的”，未解释公司名尾缀常见用法 | 补独立缩写释义，原词条级字段仍保留 |
| `ii` | 中文只给 Image Intensification 缩写，英文回退已含数字 2 | 拆分缩写与罗马数字用法，不用同形词头互相覆盖 |
| `UVC` | ECDICT 只给“万能接头”，常见 UV-C 用法没有覆盖 | 核对大小写/领域后补义项，不能用单个缩写义覆盖全部 |
| `Nussbaum's braceiets` | 原词头 `braceiets` 疑似拼写错误 | 回查原 CSV 与目标医学词形；错误源词保留追溯，必要时加规范别名 |

这些疑点中，`hell chicken` 的中英文内部矛盾最直接；其他词也可能有多种合法领域义，不能仅凭同形词猜测覆盖。当前候选仍包含原始上游文字，不能据 210 条程序一致性就给词义质量盖章。

## 40 条音频样本

从 `qa/audio-review-sample.csv` 逐条打开候选目录的 OGG 文件，重算 SHA-256，核 OGG 容器标记、文件名与词头、作者/许可/链接字段及 Commons 文件页；**40/40 条元数据与本地字节一致**。此前 `verify-audio` 对全部 436 条离线录音检查哈希和署名；固定清单还记录了逐文件的 Commons 在线元数据复核。结果保存在[音频复核表](qa/0.0.1/agent-audio-review.csv)。文件名匹配与许可字段存在，不能证明录音声波确实说出了目标词或发音自然。

为推进听辨，本轮把 40 条录音在本机交给 `Systran/faster-whisper-base.en` 做**离线辅助转写**，[原始输出与时长](qa/0.0.1/asr-review.json)已保存。多数录音只有约 0.3–1 秒：`be→B`、`see→C`、`high→Hi`、`seem→seam`、`role→roll` 等是同音/近音或短音频识别歧义；`erm→Um` 也可能是口语音近而不是源文件错误。base.en 把 `life`、`wall` 误识别成 `Nice`、`Well`；第二个 `Systran/faster-whisper-small.en` 模型对这两条分别转写为 `Life`、`wall`，[九条交叉检查](qa/0.0.1/asr-crosscheck.json)另存。这降低了“文件明显放错词”的疑虑，仍不是真人听辨。`issue→issue or issue` 可能包含两个读音，不能当成两个词。ASR 没有更改任何录音资产或把 40 行的 `content_listening` 改为通过。

## 使用结论与剩余动作

**词典本身现在可以供词遇桌面端和插件端开始接入开发**：固定的 SQLite/JSONL、5,000 词核心包、完整无音频包、带 436 条录音的完整包都已在本地生成并通过深度校验、外层与成员哈希检查及隔离解包抽验。消费端按 [CLIENT_CONTRACT.md](CLIENT_CONTRACT.md) 验证清单与 schema 即可开始；真实客户端接入测试在对应项目进行，不再挡住词典项目的开发交付。

**当前还不是应让生产客户端自动下载的正式 Release**：包内明确写着 `candidate-needs-human-review`。要把 0.0.1 从候选提升为公开默认包，还需对上述疑点给出修订/接受结论、完成独立词义判断及录音听辨，并在维护者推送 `main` 后让候选 Actions 从固定输入独立重建。任何数据修正或状态提升都要重新生成三个归档、详情 Markdown 与 SHA-256 清单。无需等待桌面端/插件端原生集成测试才能发布词典自身资产，但不能把本轮机器检查称作那两个客户端的验收。
