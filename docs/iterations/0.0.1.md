## 目标与采用的边界

按照产品选择，无音频版将公共词典与音频播放解耦，点击朗读时才向 Commons 查询元数据、下载并缓存；带发音版共用词典核心，并附一批经逐文件元数据核验的高频录音。其余词继续按需缓存。两版断网都可查词，只有音频能力存在差别。避免将 TTS 或在线服务状态写进词义事实；客户端可另接设备 TTS，但本仓库当前只实现 Commons 提供方与 Python 演示命令。

词卡首选 open-dictionary v2.0 策展内容。audit 是**同一发行版**的 Wiktionary/Wiktextract 派生结构，不能当作第二个独立证据源；只在 `entry_id`、词性、词源组及义项数匹配时附加英文原义、原始标签和更多 IPA。未对齐内容显式缺失。ECDICT 在精确词头匹配时提供词条级中文、原始考试声称与频率字段；缺词时新增仅含 ECDICT 原文的回退词条。ECDICT 中文不挂到任一英文义项，旧音标单独存 `legacy_phonetic`。CMUdict 的 ARPAbet 与 IPA 分开；WordNet 作为独立概念网络，词头命中只是候选，并非已确认的 sense 映射。

qwerty-learner 的词表索引和分类交互仍为参考，不导入来源不明的词表成员、译文或录音。DictionaryByGPT4 长文也不进入默认包：open-dictionary 已有 `memory_hook`/`study_notes`，追加长文须证明增量价值并核事实与权利。上述取舍不妨碍以后通过逐词表授权和独立助记模块扩展。

## 输入与可复现性

构建前对五个实际输入逐文件 SHA-256/字节数核验，精确值见 `sources.lock.json` 和 `docs/SOURCE_LOCK.md`：open-dictionary v2.0 distribution/audit，ECDICT `ecdict.csv`，CMUdict `cmudict.dict`，Open English WordNet 2025 Edition JSON ZIP。压缩版 distribution/audit 哈希与发行方 SHA256SUMS 一致；另对流式解压字节复算哈希，不把解压文件落到受限磁盘。Kaikki 2026-09-02 dump 与 v2.0 的 2025-10-23 谱系不同且解压约 23.9 GB，本迭代没有拿它按词头补义项。

所有输出 JSON 使用确定性键序；JSONL 稳定排序并以 `gzip mtime=0` 写出。SQLite 只读查询包由同一规范词条构建；`manifest.json` 记录输入、输出的字节数及 SHA-256，`verify` 复核完整文件和 SQLite `quick_check`。`edition.no-audio.json`/`edition.with-audio.json` 另将两个可安装形态指向共享核心与独立音频清单。发布时仍需把最终构建代码 commit 与人工审核记录一并保存；不能仅靠输入 Git 子模块指针复现 Release 数据。

`package` 对两个版本分别生成完整 `tar.gz`，归档文件名、路径顺序、uid/gid 与时间戳固定；`dist/release-candidate.json` 保存两个归档的字节数与 SHA-256。该操作只生成本地候选，不触发 GitHub Release。

策略调整前旧归档实测：无音频版 432,077,835 bytes，SHA-256 `5a66ccd21b6779d59d8813e9002fc84bec569c42ae675efa5370fbe6d1148515`；带发音版 436,748,741 bytes，SHA-256 `de6a13e075c4f8a4783feb3fbcc170b0c905a7c153c26e047c373bb229850b26`。当时逐个重新计算哈希并遍历 tar 成员：无音频版 13 个文件且无音频资产，带发音版 468 个文件含 454 条录音。两个归档都保留当时的数据许可和源声明，差值约 4.67 MB 是压缩后的音频增量；新源码尚未重建，不能直接沿用这些 SHA-256。

## 音频与发布剩余门禁

Commons 官方 `imageinfo` API 已用于真实音频核权。500 个按 ECDICT 历史词频序位选出的高频候选中，454 条录音进入带发音版，内容合计 6,046,237 bytes；其中 448 条为 CC BY-SA 3.0，6 条为 CC BY-SA 4.0。46 条被跳过：45 条许可不在白名单，1 条缺作者或许可 URL。每个成功文件都有作者、许可 URL、Commons 文件页、媒体类型、字节数和 SHA-256；失败原因在 `build/v0.0.1/audio/manifest.json`。构建器对短暂网络错误有重试。文件名须保守匹配词头/词性，不承诺每个高频词都有真人录音。`verify-audio` 已对 454 个文件逐条复算哈希并检查署名字段。

发布代码与公开数据包必须分开判断。目前阻断**公开数据包或 0.0.1 正式 Release**的门禁：用新源码重新全量构建并核对 SHA-256；200 条分层样本的人工义项/标签/读音审核；离线音频逐文件署名抽查；实际浏览器插件与桌面端的安装、断网、哈希拒绝、升级回滚和用户单词本隔离测试。ECDICT 采用上述署名和权利通知策略，不再要求逐字段核权先于发布。未完成前新源码保持 `candidate-needs-human-review`，不把包体积或词条数单独说成产品质量胜过 open-dictionary。
